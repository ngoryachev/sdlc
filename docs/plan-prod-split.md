# Мини-план: неубиваемый sdlc (прод отдельно от разработки)

## Зачем
Сейчас служба работает прямо из `~/Develop/sdlc`. Любой Land или ручная правка меняют промпты и yaml у работающего сервера до пересборки, а агент из worktree может поднять второй сервер на боевой базе. Цель: менять sdlc самим sdlc без риска для идущих задач.

## Изменения

1. **Замок единственного экземпляра** (`server/src/cli/serve.ts`)
   - При старте `serve` создаёт `<data_dir>/server.lock` с pid.
   - Если файл есть и процесс с этим pid жив, сервер пишет понятную ошибку и выходит с кодом 1, не открывая базу.
   - Мёртвый pid: замок перезаписывается. При штатной остановке файл удаляется.
   - Тест: второй `serve` на том же `data_dir` падает, на другом `SDLC_HOME` стартует.

2. **Скрипт выкатки** (`deploy/update.sh`)
   - `cp sdlc.db sdlc.db.bak` (откат миграции = вернуть файл и предыдущий коммит).
   - В каталоге прода: `git pull --ff-only`, `npm ci`, `npm run build`, `npm test`.
   - Только при зелёных тестах: `systemctl --user restart sdlc`, затем проверка `/api/health`.
   - Любой шаг упал: выход без рестарта, старая версия продолжает работать.

3. **Перенос службы** (разовая операция, не код)
   - `git clone` репозитория в `~/.sdlc/app`, сборка, тесты.
   - В `~/.config/systemd/user/sdlc.service`: `WorkingDirectory=%h/.sdlc/app`, `daemon-reload`, `restart`.
   - Делать, когда задачи стоят на чекпоинтах или простаивают.

4. **Снимки начатых задач** (разовая операция)
   - В `pipeline_runs.pipeline_snapshot` у незавершённых run заменить `~/Develop/sdlc/pipelines` на `~/.sdlc/app/pipelines` одним SQL `UPDATE … replace(…)`.
   - Без этого начатые задачи продолжат читать промпты из `~/Develop/sdlc` до своего завершения (работает, пока каталог на месте).

5. **Документация** (`README.md`, `CLAUDE.md` в корне)
   - README: раздел «Обновление» с `deploy/update.sh`.
   - CLAUDE.md для агентов: живой запуск только с `SDLC_HOME` во временной папке и на другом порту; службу не трогать.

## Что не входит
- Ограничение прав агента (gh из keyring, ssh): отдельное решение, сознательно отложено.

## Проверка
- `npm test` зелёный, новый тест на замок проходит.
- После переноса: `systemctl --user status sdlc` показывает `~/.sdlc/app`; идущая задача продолжает фазу; правка промпта в `~/Develop/sdlc` не влияет на новую задачу.
- `deploy/update.sh` с намеренно красным тестом не перезапускает службу.
